# 个人最佳：跑步与骑行功率

新版首页的“个人最佳”卡片可通过左右箭头循环翻页：

- 跑步：400 米、1 公里、5 公里、10 公里、半马、全马。
- 骑行功率：5 秒、1 分钟、5 分钟、20 分钟、40 分钟、1 小时的最佳平均功率。

点击有成绩的项目可查看对应活动。没有有效成绩时显示 `--`。

## 数据来源

跑步读取 Strava 活动详情的 `best_efforts`，使用包含停顿的 `elapsed_time`。
同步范围为至少 400 米的 Strava 跑步活动。`best_efforts_version=2` 表示已经
按六个标准距离同步；旧的四距离缓存会自动补抓一次。

骑行读取 Strava 的 `time`、`watts` 完整数据流，仅采用 `device_watts=true`
的实测功率。结果属于本站根据 Strava 数据计算的成绩，不代表 Strava 官方功率曲线。
支持普通骑行、室内虚拟骑行、山地、公路碎石和电助力骑行的骑手实测功率。

计算使用实际经过时间，按采样区间对功率积分，零功率计入平均值。
单个采样值覆盖从该时间戳到下一时间戳的区间，不向最后一个采样点之后外推。
无效值、负值或超过 5 秒的采样间隔会断开连续区间；不跨越中断拼接纪录。
因此长时间成绩可能与 Strava 的暂停处理方式不同。没有足够长的连续数据时不生成该时长成绩。

## 同步与回填

常规 `strava_sync.py` 会分别处理最多 20 条待同步跑步和骑行活动。
结果及同步时间保存在 SQLite，并随活动数据导出到前端 JSON。空数组表示已检查但
没有符合条件的成绩；尚未同步或接口暂时不可用的记录保持待同步状态。

凭据使用项目现有 `.env` 中的 Strava 配置。手动补齐历史数据：

```powershell
.venv\Scripts\python.exe run_page\strava_best_efforts.py --sport all --limit 0
```

可用 `--sport run` 或 `--sport cycling` 只同步一种运动。
在 Strava 裁剪活动、修改成绩或替换功率数据后，加 `--refresh` 重新计算。
同步会逐条提交，API 错误或限流后可以再次运行并从缓存继续。

2026-10-15 的首次升级按近期成绩优先：已保留抓取完成的跑步和骑行成绩，
剩余 64 条旧跑步活动按用户要求结束回填，并标记为当前版本。旧活动已有的
成绩继续保留；未抓取过的成绩使用空数组，不补写实际同步时间。
后续普通同步只处理新活动，若以后需要重新检查这些旧活动，可使用 `--refresh`。
